# План разработки монитора ресурсов

Статус: план подготовлен, выполнение T1–T6 не начато.

Источник требований — [SPEC.md](SPEC.md). Решения DG1–DG5 и доступные аккаунты фиксируются в разделе 11 спецификации; этот план определяет задачи, зависимости и порядок выполнения. Текущая авторизация ограничена сохранением документации в первом локальном коммите, без реализации и push.

## Порядок и граница доставки

Порядок: T1 → T2 → T3 → T4 → T5 → T6. T3–T5 технически опираются на T1–T2 и могут исследоваться независимо, но реализация в общем checkout выполняется последовательно. Неопределённость отдельного провайдера не должна блокировать независимую готовую работу после разрешения на выполнение.

Первый полезный срез — несколько аккаунтов Codex после T3. Полная первая версия требует выполнения всего согласованного покрытия и приёмки T6. Значение `unsupported` не заменяет выполненную интеграцию; изменение объёма фиксируется отдельным решением пользователя.

Общий DoD кодовых задач: выполнены AC, пройдены целевые проверки, просмотрен фактический diff, результат и ограничения зафиксированы в checkpoint соответствующей задачи, изменения закоммичены локально. Push, merge и публикация не входят в границу доставки. Команды проверок определяются после выбора стека и записываются вместе с фактическими результатами; непроведённая проверка не считается успешной.

После разрешения на выполнение нескольких задач применяется delivery-owner: root → свежий batch_owner → worker и при необходимости test_monitor. Один владелец пакета и один автор изменений одновременно; root принимает завершённый пакет до следующего. Перед закрытием всей первой версии проводится независимая epic_qa. Планирование и этот первый коммит не запускают данный процесс.

## T1. Подтвердить источники и покрытие

Status: todo

Goal: определить реализуемые источники показателей подписок/пользовательских планов и API для всех трёх провайдеров.

Scope: матрица «провайдер × тип ресурса × метрика», способы авторизации и изоляции аккаунтов, права, свежесть, ограничения опроса; выбор минимального серверного стека. Для Claude отдельно исследуется бесплатный аккаунт. Приоритет API — баланс/кредиты и остатки квот.

Out of Scope: продуктовый код, покупки, переключение рабочих учёток и изменение существующих авторизаций.

DoR: выполнен для исследования — известны провайдеры, требования и доступный набор аккаунтов; выполнение задачи ещё не запрошено.

DoD: в разделе результатов T1 этого документа сохранены матрица покрытия, ссылки на источники, проверенные факты, неизвестные условия и решения по стеку; документация закоммичена локально. Доступные безопасные проверки описаны с результатами; требующие отсутствующего доступа выделены отдельно.

AC:
- Для каждого из шести сочетаний провайдера и типа ресурса определены источник и его статус: подтверждён, кандидат или недоступен по установленной причине.
- Указаны применимость 5h и других окон, смысл единиц, время наблюдения, права и способ изоляции учёток.
- Определены допустимые исключения из опроса 10 секунд и правила свежести; пассивные данные не выданы за независимое обновление.
- Зафиксированы точные обязательные API-метрики либо решение, которого не хватает для их утверждения; DG3/DG4 не закрываются на основании предположений.

Dependencies: публичная документация; доступ к аккаунтам и API-правам для живых проверок, наличие которых пока не подтверждено.

Notes/Risks: 2 GPT, 1 GLM, 1 бесплатный Claude не доказывают наличие API-доступа. Исследование может завершиться доказанным ограничением, при котором соответствующая реализация останется `needs_design`.

## T2. Сделать общий экран и цикл обновления

Status: waiting_dependency

Goal: отображать ресурсы нескольких аккаунтов в одном локальном цветном TUI веб-интерфейсе.

Scope: сервер на loopback, конфигурация аккаунтов, нормализованная модель, экран и подробности, фильтр, локализация `en/ru` через серверный конфиг, ручное обновление и общий опрос 10 секунд, кэш в памяти и состояния ошибок/свежести.

Out of Scope: реальные интеграции, история, уведомления, удалённый доступ, переключатель языка в браузере.

DoR: T1 определил стек и контракт, достаточные для общей части; DG1/DG2 закрыты. Все источники не обязаны быть подтверждены, если их неопределённость не меняет этот контракт.

DoD: общий DoD; проверка интерфейса на Linux в браузере для обеих локалей, автоматические проверки преобразований и переходов состояний, проверка origin/Host и отсутствия секретов в ответах.

AC:
- Несколько аккаунтов любого провайдера и типа ресурса изолированы по идентификаторам; для каждого видны все применимые окна, включая 5h.
- Ноль, неизвестное значение, устаревшие данные и ошибка различимы; сброс окна не создаёт выдуманный остаток.
- Медленный источник не задерживает другие; попытки одного источника не перекрываются и не накапливаются; дополнительные вкладки не умножают внешний опрос.
- Реализованы требования экрана, клавиатуры, цвета и локализации из раздела 4 SPEC.md; демонстрационные данные явно обозначены.

Dependencies: T1; SPEC.md, разделы 4–6, 8–10.

Notes/Risks: моковые источники подтверждают общую логику, но не работоспособность интеграций. Смена языка требует перезапуска и подчиняется общему сбросу кэша.

## T3. Подключить Codex и OpenAI API

Status: needs_design

Goal: показывать показатели нескольких аккаунтов Codex и отдельно согласованные метрики OpenAI API.

Scope: источники из T1, привязка авторизации, преобразование метрик, окна лимитов, независимые ошибки аккаунтов; подписки и API имеют раздельные источники.

Out of Scope: автоматическое переключение рабочих CLI, запросы моделям, покупки и расходование reset-кредитов.

DoR: T1 подтвердил способ изоляции, применимость двух GPT-аккаунтов к Codex, API-контракт и необходимые права; T2 завершён. Неразрешённый API-объём требует уточнения задачи до её запуска.

DoD: общий DoD; живое сравнение показателей двух аккаунтов для каждого поддерживаемого типа ресурса; автоматические проверки разбора обезличенных ответов и ошибок авторизации.

AC:
- Аккаунты и API-проекты не смешиваются; обновление и ошибка одного не перезаписывают другой.
- Все доступные применимые окна показаны отдельно с временем сброса и наблюдения.
- Монитор не меняет активную рабочую учётку и не конфликтует с обновлением токенов CLI.
- API-баланс/квоты показаны с подтверждёнными единицами и областью действия.

Dependencies: T1, T2, доступные учётки Codex и API-проекты с достаточными правами.

Notes/Risks: наличие двух GPT-аккаунтов само по себе не закрывает DoR или требование живой проверки API.

## T4. Подключить Claude

Status: needs_design

Goal: показывать доступные показатели Claude, включая исследованный бесплатный план и отдельно согласованные API-метрики, с честной свежестью.

Scope: подтверждённые источники из T1, поддержка нескольких учёток, отсутствующих окон и истёкшей авторизации; пассивный источник допускается только после решения DG4.

Out of Scope: платные запросы ради обновления, покупка подписки, предположение о доступности Claude Code по наличию бесплатного аккаунта.

DoR: подтверждена применимость источника к нужным планам, закрыты необходимые решения DG3/DG4, доступна авторизация для реализации и проверки; T2 завершён.

DoD: общий DoD; сверка на доступной реальной учётке, проверки отсутствующих/устаревших данных и изоляции на обезличенных ответах. Обязательная проверка двух реальных учёток и API-покрытия должна быть завершена для `completed`; при её отсутствии результат остаётся `review` с указанной зависимостью.

AC:
- Бесплатный план не получает метрики платного по предположению; недоступность данных имеет конкретную причину.
- При наличии применимых 5h и других окон они отображаются независимо.
- Повторное чтение неизменного снимка не обновляет время наблюдения; API-расход не подменяет остаток плана.
- Независимость нескольких аккаунтов соответствует общему контракту.

Dependencies: T1, T2, источники и права Claude; вторая реальная учётка для полной приёмки, сейчас отсутствует.

Notes/Risks: DG5 открыт. Если источник для бесплатного Claude не найден, нужно решение по покрытию; `unsupported` не закрывает задачу автоматически.

## T6. Проверить готовность первой версии

Status: waiting_dependency

Goal: получить воспроизводимый запуск и доказанное выполнение согласованных требований.

Scope: инструкция запуска, конфигурация без секретов, итоговая проверка всех критериев SPEC.md и независимая приёмка стабильной ревизии.

Out of Scope: удалённый хостинг, публикация и распространение приложения.

DoR: реализация T2–T5 завершена, точное покрытие согласовано; доступны среды и учётки для обязательных проверок либо явно согласованы исключения. Недостающие живые проверки не считаются выполненными.

DoD: общий DoD; все обязательные проверки SPEC.md имеют результаты и свидетельства; независимая epic_qa дала `pass` или `pass_with_notes` на фиксированной ревизии. При согласованном исключении отдельно записываются невыполненный критерий и принятый риск; технический результат не переименовывается в успешный.

AC:
- Приложение запускается по инструкции; добавление аккаунта не требует изменения кода.
- Проверены штатный опрос 10 секунд, несколько вкладок, тайм-ауты, `401/403`, `429`, некорректные ответы, частичные данные и сброс окон.
- Проверены две локали через конфиг, цветной TUI, клавиатура, защита секретов и локальный доступ.
- Покрытие всех провайдеров и типов ресурса подтверждено; открытые ограничения не скрыты за `unsupported` или успешными мок-тестами.

Dependencies: T2–T5, SPEC.md раздел 10, доступ к недостающим реальным аккаунтам/правам по DG5.

Notes/Risks: имеющегося набора аккаунтов пока недостаточно для полной живой приёмки. Проверки с общими ресурсами выполняются последовательно.
